A visual language for Opintel

The console asks someone to make irreversible decisions about data they cannot see. Every concept it deals in — a treatment, a state, an object, a direction of change — should be recognisable before it is read. This proposes the marks.

Exposure is a spectrum

One base shape, filled according to how much of a value reaches an agent. A screen then looks permissive or restrictive before anyone reads a word, and a change is visible as movement along the axis.

  • Fill carries exposure. Solid is the whole value; an outline is none of it. Nothing about the spectrum depends on colour, so it survives a monochrome export and a reader who cannot distinguish hues.
  • Tokenized is an outline with a centre. No value reaches the agent, but something persists: the same input always produces the same token. The dot is that persistence.
  • Aggregate is three marks, not one. The value exists only as part of a group, and the mark says so.
  • Undecided is the only dashed mark and the only yellow one. It is not a sixth treatment: it is work waiting. Yellow already means “needs your decision” in this console, and it sits behind an ink outline rather than carrying the line.
  • Withheld is grey, undecided is yellow. Both show nothing to an agent and they are entirely different situations. One is a decision; the other is its absence.

  • Recognition beats system here. A database looks like a database and an agent looks like an agent, because nobody should have to learn what a triangle means. The treatments above are the opposite case: they are concepts only this product has, so they need a system that teaches how they relate.
  • One colour accent each, at most. The engine's status light and evidence's check are the only departures from a single ink, and each carries a fact.
  • A pool is two agents, not an abstraction. It is an audience, and the mark says so without a legend.

Request kinds

Activity mixes three kinds of request, and they leave different evidence behind. A reader scanning the list should see which without reading.

Query

  • Prompt is the only one in plum. A query is a statement; a prompt passed through a model that decided what it meant. The interpretation is the part that can be wrong, and the colour says to look at it.

  • Observations and "needs a decision" share a mark. That is the point: the drawer item and the state it collects are the same idea, and a reader should connect them without being told.
  • Audit log and Source of truth both use a check. One on a document, one on a circle — a verified record against a verified fact.

Which way a change goes

The console's existing audit convention has the right instinct: in a governance product the risky act is the permissive one. This makes it a visual rule rather than a colour choice in one screen.

Exposing

More reaches an agent than before. Reversible as configuration, not in consequence: once a value has been read, it has been read, and a record says so.

Restricting

Less reaches an agent than before. Answers already given are unchanged; future ones carry less.

Weight, before the click

The same control, carrying what it will do. Not a confirmation dialog — those train clicking through — but the consequence in the view where the decision is made.

23 elements will become readable by Reporting. Agents have asked for 4 of them. Answers already given are unaffected; future answers will include these values.

What this is not

  • Not decoration. Every mark carries one fact that is otherwise only in text. Anything that adds no information does not earn a place, because a screen where everything is decorated has nothing that stands out.
  • Not a colour system. The spectrum reads in monochrome. Background fills distinguish undecided from decided; ink arrows distinguish exposing from restricting.
  • Not new tokens. Everything here is drawn with --plum, --ink-2, --ink-3, --ink, --yellow-bg, --green-bg and --green-dk. The values on this page are the real tokens from docs/opintel-master.css.

A proposal, not an implementation. If the marks are right, they become a small set of inline SVGs in the master stylesheet's existing badge and row patterns, used everywhere a treatment, a state, an object or a direction appears — the entitlements tree, the schema explorer, evidence records, suggestions, the dashboard feed and the agent twin.
