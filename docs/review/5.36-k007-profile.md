## Custody path audit and correction

MCP dispatch previously called `ReleaseRuntime.isConfigured` on **every tool call** when the production runtime was installed. That adds a project settings/check read even to an ordinary query. It now runs only for `opintel.redeem`; tool listing still checks whether redemption should be advertised. This preserves hidden/unconfigured redemption behaviour and removes unnecessary query-path configuration work.

For K-007, sealing setup, release-key generation, split, escrow, signing and provider checks have zero invocations by construction: the fixture contains no custody column and installs no release runtime. Production sealing is conditional on nonempty authoritative custody result indices. Provider availability checks remain conditional on a **referenced** custody column, including predicates, as required by the previously approved fail-closed policy; a clear projection with no custody reference skips them. Checking a custody predicate cannot wait until output sealing. The Activity custody summary is an Activity read-model operation and is never called by this MCP query path. The additional lineage bookkeeping does not perform release cryptography.
