# 5.33 Dashboard: shared read models and scoped geometry

The three bands are Needs you, Where the project stands, and Recently. Needs
you is absent when there are no current findings. A finding is a number,
a one-line explanation, a small factual visual, and the resolving action.

Counts come from destination APIs: entitlement groups per pool, open observation
groups (custody only with administration permission), open suggestion pages,
Activity summary/day counts and recent evidence rows, and current pool presence.
Every cursor needed for a total is traversed. Failed reads show an error rather
than a partial total or a false clean state. No source values or overlap analysis.

Entitlement cards are scoped to a pool: the count and Decide link select the
same undecided members, with exact grouped-name count from that scope. Project
exposure counts pool–element decisions, never unique elements. Demand says
Join attempted; only recorded query/explain attempts establish it. Observation
links carry the Open view and their kind/group so that a filing count is not a
link to an interleaved list of unrelated findings. Suggestions include pending
and Not sure; confirmed/rejected history is not open work. Recent requests link
to their evidence permalink and keep 5.32's historical object-count fallback.

Seven-day request, refusal and incomplete trends use UTC calendar days, labelled
once Last 7 days (UTC). Today's links carry the same UTC range/outcome/mode.
Presence is current, not a historical series; no agent sparkline is invented.
No treatment-history feed event is reconstructed from overwritten entitlements.
Existing setup guidance, failed source checks and custody findings remain.
