# 5.35 Data sources: implementation contract and proposed master variants

Specification: `docs/DataSources.html`; live behaviour remains catalogue/declaration contracts, algorithm A.3 and existing source/filing semantics. No source values are sampled. No visual project or baseline regeneration during screen review.

## Existing capabilities and gaps

Source registration, Engine selection, connection testing, demo provisioning states, introspection/retry, filing expansion and declaration GET/PUT routes exist and are mounted. Preserve their permissions, errors and recovery. Source listing has readable names/aliases, element/unsupported/undecided counts and last introspection. It lacks object count, last landed timestamp, quarantine summary and exposure distribution. Add tenant-scoped metadata reads, not browser guesses. Filings remain labelled according to their actual outcomes; never label a total including quarantines as landed. Engine display name comes from the registered Engine, never a UUID fallback presented as a name.

The current tree reader returns source → schema → object → element and assigns every supported element `undecided` without consulting entitlements. Add a source-scoped, cursor-paged object level and real treatment summaries/declarations. Do not fetch every declaration panel or Engine canonicaliser inventory to draw chips. Keep schema names available for disambiguating identically named objects and full paths in titles/accessibility; suppress generated source/schema *levels*, not namespace information. Deep-linked elements still load independently of the window.

Treatments are pool-specific. Source exposure follows Dashboard's pool–element decision counting and says so; source element totals remain unique elements. An element with different treatments across pools shows the treatments present rather than choosing one. Existing awaiting-decision count remains unique supported/nameable elements missing a decision in at least one pool (or all such elements when there are no pools). Never describe these different denominators as the same count. Object summaries use the same rules. An empty project has no invented pool decisions.

Prototype corrections: use actual master tokens; no source kind mark plus connection state mark on the same card; no general “asked for” assertion from refused joins. Any displayed demand is “Join attempted”. Applicability follows effective mode: timezone is needed for naive timestamps, not zoned timestamps or text; epoch only applies to integers, case folding to text; retain stored legacy declarations visibly even where unused, without offering an inapplicable editor. Canonicaliser compatibility and effective-behaviour typed confirmation remain enforced. Existing historical evidence is untouched.

Demo explanation and all three provisioned/connected states move into the connect flow; an already-connected source carries the Demo data tag. The source list no longer repeats pack narrative.
