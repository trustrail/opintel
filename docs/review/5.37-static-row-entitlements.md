# 5.37 step 2: static row entitlements

This slice implements static predicates only. It does not implement scope references, SpiceDB scope relationships, the credential challenge or issuer admission. The comparison contract is recorded in [the design position](row-scoping-design-position.md#static-comparison-contract--decided-537-step-2); §3.6 now describes read-boundary enforcement and separate filter-only inputs.

## Implementation

Migration 074 records immutable object × pool decisions with actor, time, typed predicate, normalised hash and a first-scoping event. Current decisions are resolved at architecture step 3. A changed catalogue input fails closed until its decision is reviewed. Decision writes advance the existing policy version. Administrator-only history resolves receipt hashes without exposing predicate literals to agents.

The PostgreSQL translator uses explicit binary collation. The Engine evaluates SQL three-valued logic and exact decimal/represented-float comparisons. PostgreSQL fixed-width text is read without the implicit trimming performed by a text cast. Unsupported source/type mappings fail closed. PostgreSQL is the implemented source translator; another source must supply and pass the comparison conformance contract before receiving pushdown.

Clear scope inputs permit pushdown. All other inputs are read separately, filtered before treatment, and excluded from staging and returned columns. A scoped object without this pool's decision creates an empty staged object without contacting its source, returns no rows, records the cause and produces a targeted Needs You finding. Disclosure thresholds apply after scoping.

Row facts survive evidence sampling and retention. They contain decision identity, hash, referenced names, admitted count and credential provenance, never predicate literals or table totals. Historical receipts remain unchanged. Activity shows the first-scoping event and the receipt's row facts; a historical receipt without scope facts is quiet until expanded metadata shows “Rows: unscoped at the time of the call”.

Entitlements → By table offers Rows/Scoped beside each object. Its editor uses existing master patterns, validates at save and exposes immutable decision history. Saving invalidates entitlement reads (including decision/history), project statistics/Dashboard and Activity; it does not invalidate exposure data as a new column treatment.
